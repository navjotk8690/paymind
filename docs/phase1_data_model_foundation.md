# NavCore PayMind
## Phase 1: Data & Model Foundation

NavCore PayMind – Phase 1: Data & Model Foundation
Objective

The objective of Phase 1 was to establish the data foundation required to build an intelligent payment routing engine capable of predicting:

the most suitable payment connector,
probability of payment success,
expected settlement time,
future routing decisions.

The focus was on creating a clean, privacy-preserving machine learning pipeline rather than training production models immediately.

Architecture Decisions

The system is designed as a stateless AI decision engine, not as a payment gateway.

Core design principles:

REST API based
Connector/plugin architecture
No storage of customer or transaction data
Models remain private
Connectors and interfaces remain open source
High-performance inference (<100ms target)
Independent of payment providers
Machine Learning Architecture

Three independent prediction models were defined.

Model 1 — Payment Method Recommendation

Purpose

Target:

payment_type

transaction type

Model 2 — Success Prediction

Purpose:

Estimate the probability that a payment succeeds when routed through a specific connector.

Target:

success (0/1)

Output:

0.92

meaning

92% probability of success

Model 3 — Settlement Time Prediction

Purpose:

Predict expected arrival time of funds.

Target:

arrival_duration_minutes

Output example

615 minutes

10.2 hours

Data Extraction

Training data was extracted directly from historical production records.

The exported datasets contain more than five years of historical payment activity.

The exported data is anonymised and excludes customer-identifying information.

No personal information is required for model training.

Data Inspection Framework

Validation includes

The inspector also generates machine-readable reports for further analysis.

Data Quality Findings

Several important observations were made during inspection.

Connector Distribution

Three payment methods account for approximately 83% of all historical transactions.

MCB
Checkout
Worldpay

Several connectors contain only a handful of observations and may require grouping or exclusion during training.

Suspicious Input Detection

Historical exports contained malformed currency values generated by security scanners and penetration testing.

Examples included

XSS payloads
OWASP scanner URLs
directory traversal strings
malformed HTTP requests

These records will be excluded from model training while remaining useful for security analysis.

Temporal Behaviour

Connector popularity changes significantly over time.

Several connectors disappear while new connectors emerge in later years.

Therefore chronological train/validation/test splits will be used instead of random sampling.

Selected Machine Learning Framework

CatBoost was selected as the primary modelling framework because it:

performs exceptionally well on structured tabular data
naturally handles categorical variables
requires minimal feature engineering
provides calibrated probability outputs
offers fast inference suitable for API deployment
supports multiclass classification and regression

Alternative algorithms (XGBoost, LightGBM, Random Forest, Neural Networks) were evaluated conceptually but CatBoost was chosen as the primary engine for Version 1.
